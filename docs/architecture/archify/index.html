What this repo does at runtime

Stamped’s L6 control-room is a Next.js web app on port 3000 backed by a Fastify BFF on port 3001 that owns sessions, upstream keys, and Postgres. Operators use Overview, Live, Alarms, Prescriptions, Ask Analyst, and Evidence routes; each page calls BFF /api/* endpoints that choose live L2/L4/L5 HTTP or fixtures based on USE_FIXTURES and L*_LIVE gates. The shell polls /api/meta/upstreams to label Live vs Preview (upstream reachability—not a customer plant). Ask Analyst: with L4_LIVE off the UI shows a Preview fixture reply; with L4_LIVE on L4 returns 503 ASK_MOVED and the UI shows Analyst unavailable (L6-03). Ledger rows pass sanitizeClaimStatus before badges render. L5 events are polled every 30s into l5_events; SSE exists on the BFF but the web app refetches pages instead of subscribing; WhatsApp notify/inbound is wired with a stub for card actions.

The diagrams, explained

L6-01 — L6 control-room components

architecture · answers: How is the control-room app built?

The map ties the browser, Next.js, Fastify BFF, Postgres, worker, and L2/L4/L5 upstreams. Live gates and service keys stay server-side on the BFF. The worker handles async report/webhook queues, not L5 poll ingest.

Start with the guided view "Browser to BFF".

L6-02 — Page load — Live vs Preview gates

sequence · answers: Live vs Preview on page load

Route data loads through the BFF according to fixture and live flags; a separate upstream probe drives the connection pill. Live means the BFF reached configured L2/L5 (and L4 when L4_LIVE); Preview means fixtures or an upstream is down—not a live customer plant. The UI label “Live plant connected” can mislead.

Start with "Live vs Preview pill".

L6-03 — Ask Analyst turn

sequence · answers: Ask Analyst request path

UI posts a streaming message with a context envelope; when L4_LIVE is off the web layer uses fixtureAnalystReply and a Preview chip without calling the stream. When L4_LIVE is on, the BFF forwards to L4 but L4 main responds 503 ASK_MOVED (Ask ReAct retired); the BFF returns a problem JSON and the UI shows an “Analyst unavailable” message—dashed arrows show the designed successful SSE path only.

Start with "L4_LIVE on — as-built today".

L6-04 — L5 card events (split a/b)

sequence · answers: L5 change data path

Diagram (a) leads with the as-built 30s poll to Postgres; (b) leads with page refetch, then SSE API (exists, no web client), then DESIGNED HMAC ingest (dashed). Inbound L5 webhooks are not on main.

Start with (a) "As-built: poll ingest" then (b) "As-built: page refetch".

L6-05 — Claim label sanitisation

dataflow · answers: safe claim wording

Statuses are sanitized before badges so operations confirmation never reads as bill verification. Bill line refs remain the gate for a true verified label.

Start with "sanitizeClaimStatus".

L6-06 — Information architecture

architecture · answers: screens today vs planned

Upper labelled region is as-built nav (Overview, Live plant, Equipment, Alarms, Prescriptions, Ask, Evidence/Reports). Lower region is the DESIGNED target loop (Now, Card, Close, Autonomy, Constraints, Evidence, Ask)—none of those target routes exist on main (no /now).

Start with "As-built nav (main)".

L6-07 — WhatsApp owner action loop

workflow · answers: WhatsApp card actions

Assignments enqueue WhatsApp templates; inbound webhooks verify Meta signatures. Rx state mapping from button taps is still a stub.

Start with "Notify owner".
